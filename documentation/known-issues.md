| # | Issue | Status |
|---|---|---|
| 5 | The Calamares GUI walkthrough (clicking through the pages) has not been performed. | 6 | `unpackfs` source `/run/archiso/bootmnt/arch/x86_64/airootfs.sfs` exists on the built live system and `unsquashfs` unpacks it onto the target. | `TESTED` (2026-11-21) |
| 29 | Calamares failed at `unpackfs` with "Failed to find unsquashfs, make sure you have the squashfs-tools package installed": `squashfs-tools` was in the *build* host requirements but not in the ISO. Fixed: it is in `iso/packages/live-only.txt` and a `depends` of `calamares-config`; `rsync` (used by unpackfs' non-squashfs path) is in the same list. Both binaries are present in the built airootfs. | `TESTED` fixed (2026-11-21) |
| 30 | The live session did not start the installer by itself. Fixed: `hl.on("hyprland.start")` in the live `hyprland.lua` runs `/usr/local/bin/mahadevanos-installer`, which starts Calamares as root on the Wayland socket, maximizes the window (`io.calamares.calamares`), keeps one instance with `flock`, and opens a kitty terminal with the log if Calamares is missing or exits non-zero. SUPER+Q is a terminal, SUPER+I relaunches the installer. | `TESTED` (2026-11-21) |
| 31 | `partition.conf` mixed old- and new-style swap settings, so Calamares logged "Partition-module configuration mixes old- and new-style swap settings" and fell back to its built-in choice set. Fixed by keeping only `userSwapChoices`. | `TESTED` fixed (2026-11-21) |
| 32 | A real Calamares install failed at `unpackfs` with `rsync` exit 11. Cause: `partition.conf` used `fs:` in `partitionLayout`, but Calamares 3.4.2 only reads `filesystem:` (the `fs:` key exists only in `mount.conf`'s `extraMounts`). Both partitions were created **unformatted**, the mount module returns early for unformatted partitions, so `/` was never mounted and `unpackfs` wrote the 2.6 GiB squashfs into the installer's 3.4 GiB `/tmp` tmpfs until rsync filled RAM. Fixed: `filesystem: "btrfs"`. | `TESTED` fixed (2026-11-21, rehearsal) |
| 33 | The same install created **two** EFI partitions (a 300 MiB one and the 1024 MiB one from `partitionLayout`), both claiming `/boot/efi`. Cause: `PartitionActions::doAutopartition()` always prepends the ESP on EFI, sized by `efi.recommendedSize` (default 300 MiB); a custom `partitionLayout` must not list one. Fixed: the layout has only the Btrfs root and `efi.recommendedSize: 1024MiB` defines the single ESP. | `TESTED` fixed (2026-11-21, rehearsal) |
| 34 | `shellprocess.conf` used `commands:`. Calamares 3.4.2 reads that list from `script:` only; with `commands:` the job logged "No script given for ShellProcessJob" and did nothing, so no postinstall script (kernel restore, initramfs, branding, keyring, mirrors, snapshots, cleanup) would have run in a real install. Fixed: `script:` with a 1800 s timeout. | `TESTED` fixed (2026-11-21, rehearsal) |
| 35 | `mount.conf` contained a non-existent `rootSubvolume:` key, no `extraMounts` (Calamares logged "No extra mounts defined. Does mount.conf exist?" and `/proc`, `/sys`, `/dev`, `/run`, efivarfs were absent from the target chroot) and no `btrfsSubvolumes` (3.4.2 reads the subvolume layout from `mount.conf`, not `partition.conf`, so only its `/` and `/home` defaults were created). Fixed: real `extraMounts`, the `@`/`@home`/`@log`/`@cache`/`@snapshots` layout and `mountOptions` (`noatime,compress=zstd:1`) which the fstab module also writes. | `TESTED` fixed (2026-11-21, rehearsal) |
| 36 | A failed root mount previously surfaced only as `unpackfs`/rsync exit 11 after filling RAM. Added a `preflight` shellprocess instance between `mount` and `unpackfs` (`/usr/share/mahadevanos/calamares/check-root-mount.sh`) that fails with "PREFLIGHT FAILED" unless `/` is a real block-device mount point. The rehearsal tests it both ways (rejects a tmpfs directory, accepts the mounted target). | `TESTED` (2026-11-21, rehearsal) |
| 37 | Calamares sequence entries for a module instance must be written `module@id`. A bare instance id (`- preflight`) is interpreted as a module name; the live log showed `ERROR: Module "preflight@preflight" not found in module search paths` / `STARTUP: failed modules`, and Calamares showed its error page while the window-class check still passed. Fixed with `shellprocess@preflight` / `shellprocess@postinstall`; `scripts/test-boot.sh` now fails if those log lines appear. | `TESTED` fixed (2026-11-21) |
| 7 | Encryption uses **LUKS1** (GRUB cannot unlock LUKS2/argon2id). Experimental, off by default. | `EXPERIMENTAL` |
| 8 | "Install alongside Windows" with automatic resize is not offered. Dual boot works via os-prober and manual partitioning. | `PLANNED` |
| 9 | Calamares may warn about missing `ckbcomp` if the local repo was not built; keyboard conversion then falls back to defaults. | `IMPLEMENTED (untested)` |

## Security notes

- Live session has a known password (`live`) and passwordless sudo; this is
  **live-only** and removed by `99-cleanup.sh`, which fails the install if the live
  user or sudoers rule survives.
- The firewall is enabled post-install with deny-incoming, nothing allowed.
- No AUR builds as root; the ISO carries prebuilt local packages only.
